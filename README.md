# konf_pract2

Учебное CLI-приложение на Python для построения и визуализации графа зависимостей Java-пакетов Maven.

Программа самостоятельно скачивает POM-файлы через `urllib`, разбирает XML через `xml.etree.ElementTree` и строит граф обходом в ширину. Менеджеры пакетов и сторонние библиотеки для получения зависимостей в коде приложения не используются. PyYAML нужен для чтения конфигурации и тестового репозитория.

## Быстрый запуск

Все команды ниже выполняются из корня проекта в терминале macOS или Linux.

Для подготовки окружения нужен Python 3.9 или новее:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Запуск с основной конфигурацией:

```sh
./run.sh
```

Запуск с явно указанным файлом:

```sh
./run.sh tests/config.yaml
```

Обычный запуск выводит описание графа на языке D2. Порядок загрузки можно получить отдельно:

```sh
./run.sh tests/config_order.yaml --load-order
```

Флаг `--load-order` выводит зависимости раньше пакетов, которым они нужны. Исходный пакет также включается в результат. Приложение рассчитывает порядок, но не устанавливает и не запускает пакеты.

Справка по аргументам:

```sh
./run.sh --help
```

Для работы с реальным репозиторием нужен интернет. Для тестового репозитория и автоматических тестов после установки PyYAML интернет не требуется.

## Конфигурация

Пример основной конфигурации:

```yaml
package_name: junit:junit
repository: https://repo.maven.apache.org/maven2/
test_mode: false
version: "4.13.2"
max_depth: 3
filter_substring: ""
```

Все шесть параметров обязательны.

| Параметр | Что задаёт | Проверка |
| --- | --- | --- |
| `package_name` | Имя анализируемого пакета. | В обычном режиме — `groupId:artifactId`, в тестовом — одна или несколько больших латинских букв. |
| `repository` | Корневой URL Maven-репозитория или путь к YAML-файлу тестового репозитория. | Непустая строка; для URL проверяются HTTP/HTTPS, адрес и порт, для файла — возможность его открыть. |
| `test_mode` | Использование тестового репозитория вместо сети. | YAML-значение `true` или `false`, без кавычек. |
| `version` | Версия исходного Maven-пакета. | Непустая строка допустимого формата; записывайте версию в кавычках. В буквенном тестовом графе параметр сохраняется в конфигурации, но не влияет на обход. |
| `max_depth` | Максимальное расстояние от исходного пакета. | Целое число не меньше нуля. `true` и `false` числами глубины не считаются. |
| `filter_substring` | Подстрока для исключения пакетов. | Строка; пустая строка отключает фильтр. |

Относительный путь к тестовому репозиторию отсчитывается от папки конфигурационного файла. Например, в `tests/config.yaml` значение `repository: repository.yaml` указывает на `tests/repository.yaml`.

Если путь к конфигурации не передан, используется `config.yaml` в корне проекта. Путь, переданный в аргументе CLI, разрешается относительно текущей папки терминала.

### Глубина и фильтр

Исходный пакет имеет глубину 0. При `max_depth: 0` в графе остаётся только он; при `max_depth: 1` добавляются его прямые зависимости. Пакеты на предельной глубине включаются в граф, но их POM не загружаются и их зависимости не раскрываются. Поэтому отсутствие исходящих рёбер у такой вершины не доказывает отсутствие зависимостей у самого пакета.

Фильтр учитывает регистр. Для Maven он проверяется по имени `groupId:artifactId`, без версии. Если имя содержит заданную подстроку, пакет и ребро к нему исключаются, а обход через этот пакет не продолжается. Его зависимости всё ещё могут попасть в граф по другой, разрешённой ветке.

Если фильтр исключает исходный пакет, граф пуст. В режиме D2 выводится пустая строка, а в режиме порядка загрузки — сообщение об исключении исходного пакета.

## Как проходит выполнение

1. `run.sh` выбирает `.venv/bin/python`, если он существует, иначе `python3`, и запускает `src/main.py`.
2. `main()` получает путь к конфигурации и флаг `--load-order`.
3. `load_config()` читает YAML, а `validate_config()` проверяет параметры.
4. `build_graph()` выбирает источник данных: YAML-граф для тестового режима или Maven POM для обычного.
5. BFS обходит пакеты с учётом глубины, фильтра и уже обнаруженных вершин.
6. В обычном режиме `to_d2()` формирует текст диаграммы. С `--load-order` функция `get_load_order()` рассчитывает порядок загрузки.
7. `main()` печатает результат или сообщение об ошибке.

Рёбра направлены от пакета к его зависимости: `A -> B` означает, что пакет A зависит от B.

## Все функции основного кода

### `src/config.py`

**`validate_config(config, config_directory)`**

Принимает словарь настроек и папку конфигурационного файла. Проверяет наличие всех имён из константы `PARAMETERS`, типы и значения параметров, формат имени пакета, версии, URL или доступность тестового файла. Папка нужна для разрешения относительного пути к репозиторию. Ошибки накапливаются в списке и передаются одним исключением `ValueError`. При успехе функция ничего не возвращает.

**`load_config(filename)`**

Открывает файл в UTF-8 и читает его через `yaml.safe_load()`. Проверяет, что документ является словарём, и вызывает `validate_config()`. Возвращает словарь из шести известных параметров. Ошибки открытия файла, кодировки, YAML и проверки параметров передаются как `ValueError`. Дополнительные ключи YAML в возвращаемый словарь не включаются.

### `src/maven.py`

**`read_pom(config)`**

Получает настройки одного Maven-пакета и строит URL его POM по имени и версии. Точки в `groupId` превращаются в разделители папок. Например, для `junit:junit:4.13.2` относительный путь равен `junit/junit/4.13.2/junit-4.13.2.pom`. Загружает файл через `urlopen()` с тайм-аутом 15 секунд и возвращает байты. При ошибке загрузки выбрасывает `ValueError` с адресом POM. В текущей версии эта функция работает только с URL; буквенный тестовый репозиторий обрабатывается в `src/graph.py`.

**`resolve_properties(value, properties)`**

Получает строку и словарь свойств POM. Заменяет выражения вида `${library.version}` значениями из словаря. Делает несколько проходов для вложенных подстановок, без рекурсии. Число проходов ограничено количеством свойств плюс один. Когда строка перестаёт меняться, возвращает её. Если после ограничения подстановки продолжают менять строку, выбрасывает ошибку циклических свойств. Неизвестные свойства остаются в исходном виде; неизменяющаяся самоссылка также остаётся текстом.

**`parse_dependencies(content, package_name, version)`**

Принимает XML-содержимое POM, имя и версию анализируемого пакета. Разбирает XML, убирает префиксы пространств имён из тегов и проверяет корневой элемент `project`. Собирает локальные свойства из `properties` и добавляет значения `project.groupId`, `project.artifactId`, `project.version`, а также их варианты с префиксом `pom.`.

Читает только элементы `project/dependencies/dependency`, подставляет свойства и возвращает список кортежей `(groupId, artifactId, version)`. Если версия отсутствует, в кортеже остаётся пустая строка. Отсутствие `groupId` или `artifactId` считается ошибкой. Разделы зависимостей плагинов и `dependencyManagement` не добавляются в список прямых зависимостей.

**`get_dependencies(config)`**

Объединяет загрузку и разбор: вызывает `read_pom()`, затем `parse_dependencies()`. Возвращает прямые зависимости одного пакета. Самостоятельно граф и транзитивные зависимости не обходит.

### `src/graph.py`

**`load_test_repository(filename)`**

Читает YAML-файл описания графа. Проверяет, что весь документ — словарь, имена вершин состоят из больших латинских букв, а зависимости заданы списками. Каждая указанная зависимость должна быть строкой и иметь собственный ключ в репозитории. Возвращает словарь списков смежности. Ошибки чтения, YAML и структуры передаются как `ValueError`.

**`build_graph(config, config_directory)`**

Строит граф зависимостей с помощью BFS, без рекурсии. Возвращает словарь вида `пакет: [зависимости]`. В тестовом режиме ключами являются буквенные имена; в обычном — Maven-координаты с версиями, когда версии указаны в POM.

В очереди `deque` хранятся пары `(пакет, глубина)`. Функция берёт очередной пакет, получает его зависимости, применяет фильтр и добавляет новые вершины в очередь. Наличие вершины в словаре графа означает, что она уже обнаружена. Поэтому общий узел или участник цикла не ставится в очередь повторно, но ребро к нему сохраняется. Одинаковое ребро дважды не добавляется.

Перед раскрытием Maven-вершины проверяется наличие конкретной версии. Если её нет или она осталась выражением `${...}`, дальнейший анализ завершается ошибкой. При достижении предельной глубины вершина остаётся в графе без раскрытия.

**`get_load_order(graph)`**

Возвращает список пакетов в порядке «зависимости раньше зависимых пакетов». Использует алгоритм Кана без рекурсии. Для каждой вершины считает ещё не обработанные зависимости и строит обратные связи: какие пакеты от неё зависят. Сначала в очередь попадают вершины без зависимостей. После обработки очередной вершины счётчики зависимых пакетов уменьшаются; при достижении нуля они также добавляются в очередь.

Если обработаны не все вершины, в графе есть цикл и функция выбрасывает `ValueError`. Частичный порядок в CLI не печатается. Для пустого графа возвращается пустой список. Для независимых вершин может существовать несколько правильных порядков; функция выбирает порядок, определяемый очередью и расположением вершин в словаре. Результат относится к уже построенному графу, то есть учитывает его глубину и фильтрацию.

**`to_d2(graph)`**

Преобразует словарь графа в строку на языке D2. Сначала назначает вершинам идентификаторы `n0`, `n1` и далее, а имена пакетов помещает в подписи. Подписи заключаются в кавычки с помощью `json.dumps()`, чтобы корректно сохранить кавычки и специальные символы. Затем функция добавляет строки рёбер вида `n0 -> n1`.

Отдельные идентификаторы позволяют безопасно использовать Maven-координаты с точками и двоеточиями в подписях. Все вершины объявляются явно, поэтому сохраняются пакеты без зависимостей. Циклы также сохраняются. Для пустого графа возвращается пустая строка. Функция не запускает D2 и не создаёт SVG.

### `src/main.py`

**`main()`**

Создаёт парсер аргументов, читает конфигурацию, строит граф и выбирает вывод: D2 или порядок загрузки. Ошибки конфигурации и анализа печатает в `stderr`, результат — в `stdout`. Возвращает 0 при успехе и 1 при обработанной ошибке приложения. Блок `if __name__ == "__main__"` передаёт результат в `sys.exit()`. Ошибки самих аргументов CLI обрабатывает `argparse`, обычно с кодом завершения 2.

### Скрипты запуска

`run.sh` и `tests/run_tests.sh` не содержат отдельных функций. Оба определяют папку проекта, выбирают локальный Python из `.venv` или системный `python3` и передают аргументы дальше. Первый запускает приложение, второй — `unittest discover` для файлов `tests/test_*.py`. Аргумент `-v` у тестового скрипта включает подробный вывод.

## Что происходило на каждом этапе

### Этап 1. Минимальный прототип с конфигурацией

Были добавлены YAML-конфигурация, шесть параметров, проверка их типов и значений, обработка ошибок и скрипты запуска. На этом этапе при запуске выводились настройки в формате «ключ-значение».

В текущей версии чтение и проверка настроек сохранены. Исторический вывод параметров был нужен только для первого этапа и отдельным режимом не оставлен.

### Этап 2. Сбор данных Maven

Были добавлены имя пакета в формате `groupId:artifactId`, загрузка POM указанной версии и извлечение прямых зависимостей. Программа печатала список прямых зависимостей. Для сетевой загрузки и XML использовалась стандартная библиотека Python.

На втором этапе тестовый файл читался как POM. Начиная с третьего этапа тестовый режим использует YAML-описание целого графа. Файл `tests/repository.pom` сохранён как данные для автоматических тестов XML-разбора.

### Этап 3. Основные операции

Были добавлены транзитивный обход BFS, максимальная глубина, фильтр по подстроке, обработка циклов и файловый тестовый репозиторий с буквенными именами. Каждая обнаруженная вершина обрабатывается не более одного раза. Результат этого этапа выводился как текстовый список связей графа.

Все операции построения графа сохранены и используются в последующих этапах.

### Этап 4. Порядок загрузки

Были добавлены `get_load_order()` и флаг `--load-order`. Для графа без циклов рассчитывается порядок загрузки; при цикле выводится ошибка. Демонстрации включали общую зависимость двух веток, ограничение глубины, фильтрацию, пакет без зависимостей, обычный цикл и цикл на себя.

Для сравнения использовался Maven Dependency Plugin. Для `junit:junit:4.13.2` зависимости и версии совпали: `hamcrest-core:1.3` и `hamcrest-library:1.3`. Плагин `dependency:tree` печатает дерево с исходного пакета, а приложение в режиме порядка загрузки помещает зависимости раньше него. Результаты записаны в `tests/maven_comparison.txt`.

### Этап 5. Визуализация

Была добавлена `to_d2()`. Обычный вывод приложения заменён описанием диаграммы D2. Флаг порядка загрузки сохранён.

Для трёх пакетов подготовлены конфигурации, D2 и SVG. Также сохранён DOT, полученный Maven Dependency Plugin. После объединения одинаковых Maven-координат состав вершин и рёбер в трёх примерах совпал. Различия в подписях, типах, областях зависимостей и обозначении повторов объяснены в `tests/visualization/comparison.txt`.

Демонстрационные SVG созданы внешним компилятором D2. Само Python-приложение выводит только текст диаграммы.

Действия с Git и коммиты при выполнении этапов не выполнялись согласно отдельному ограничению задания.

## Руководство по тестированию

### Автоматические тесты

Запуск всего набора:

```sh
./tests/run_tests.sh
```

Подробный вывод с именами проверок:

```sh
./tests/run_tests.sh -v
```

Запуск одного модуля:

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_graph.py' -v
```

Запуск только проверки D2:

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_graph.py' -k test_d2 -v
```

В проекте 15 тестовых методов. Некоторые используют `subTest`, то есть проверяют несколько вариантов внутри одного метода. При успешном запуске общий итог содержит:

```text
Ran 15 tests

OK
```

Тесты используют встроенный `unittest`. В сетевых сценариях `unittest.mock.patch` подменяет загрузку POM, поэтому настоящий Maven-репозиторий не вызывается. Временные конфигурации создаются внутри `tests/` и удаляются после проверок. Maven, Java и компилятор D2 для автоматического набора не нужны.

### Что проверяет каждый тест

| Модуль и метод | Проверяемое поведение |
| --- | --- |
| `test_config.py`: `test_cli_graph_and_load_order` | Чтение корректной конфигурации, вывод D2 с фильтром, порядок загрузки и ошибка CLI при цикле. |
| `test_config.py`: `test_invalid_parameter_values` | Ошибочные значения каждого параметра и недопустимое буквенное имя в тестовом режиме. |
| `test_config.py`: `test_missing_parameters` | Отсутствие каждого обязательного параметра. |
| `test_config.py`: `test_test_repository_paths` | Абсолютный и относительный путь к тестовому файлу. |
| `test_config.py`: `test_unavailable_test_repository` | Отсутствующий файл и путь к папке вместо файла. |

Вспомогательные методы тестов:

- `ConfigTests.setUp()` создаёт временную папку и исходный словарь настроек, регистрирует удаление папки после теста.
- `ConfigTests.write_config()` записывает текущие настройки во временный YAML-файл.
- `ConfigTests.run_cli(*args)` запускает `run.sh` отдельным процессом, передаёт конфигурацию и дополнительные аргументы, возвращает результат процесса с `stdout`, `stderr` и кодом завершения.
- `GraphTests.setUp()` создаёт базовые настройки для чтения `tests/repository.yaml`.

### Ручная проверка тестового репозитория

Фрагмент `tests/repository.yaml`:

```yaml
A: [B, C]
B: [D]
C: [D]
D: [A, E]
E: []
F: []
G: [G]
H: [I, J]
I: [K]
J: [K]
K: []
```

Все вершины должны иметь ключ, даже если у них нет зависимостей. Пустой список `[]` означает отсутствие зависимостей.

Вывод D2 для графа с циклом:

```sh
./run.sh tests/config.yaml
```

Ожидаются вершины A, B, C, D, E и рёбра A → B, A → C, B → D, C → D, D → A, D → E. В частности, цикл A → B → D → A должен сохраниться в D2, а программа должна завершить обход.

Порядок загрузки для графа без циклов:

```sh
./run.sh tests/config_order.yaml --load-order
```

Ожидаемый результат:

```text
K
I
J
H
```

Проверка ошибки циклического графа:

```sh
./run.sh tests/config.yaml --load-order
```

Ожидается сообщение в `stderr` о невозможности определить порядок из-за цикла и код завершения 1. Частичный список загрузки не выводится.

Для остальных ручных случаев меняйте значения в копии `tests/config.yaml`, сохраняя копию в папке `tests/`, чтобы относительный путь `repository.yaml` оставался верным:

| Параметры | Ожидаемый результат |
| --- | --- |
| `package_name: A`, `max_depth: 0`, пустой фильтр | Только вершина A. |
| `package_name: A`, `max_depth: 1`, пустой фильтр | A → B и A → C. |
| `package_name: A`, `max_depth: 3`, `filter_substring: D` | Вершины A, B, C; D и E не попадают в граф. |
| `package_name: A`, `filter_substring: A` | Пустой D2; с `--load-order` — сообщение об исключении исходного пакета. |
| `package_name: F`, пустой фильтр | Одна вершина F; порядок загрузки состоит из F. |
| `package_name: G`, `max_depth: 3`, пустой фильтр | Ребро G → G; с `--load-order` — ошибка цикла. |
| `package_name: H`, `max_depth: 3`, `filter_substring: I` | Граф H → J → K; порядок K, J, H. |

Чтобы вручную проверить валидацию, в копии конфигурации укажите, например, `max_depth: -1`, `test_mode: "true"`, `package_name: a` при тестовом режиме или путь к отсутствующему репозиторию. Должно появиться понятное сообщение с именем неверного параметра. Удаление обязательного поля и повреждение синтаксиса YAML также должны завершаться ошибкой.

### Примеры визуализации трёх Maven-пакетов

| Пакет | Конфигурация | D2 | Готовый SVG |
| --- | --- | --- | --- |
| `junit:junit:4.13.2` | `tests/visualization/junit.yaml` | `tests/visualization/junit.d2` | `tests/visualization/junit.svg` |
| `org.junit.jupiter:junit-jupiter-api:5.10.2` | `tests/visualization/jupiter-api.yaml` | `tests/visualization/jupiter-api.d2` | `tests/visualization/jupiter-api.svg` |
| `org.hamcrest:hamcrest-library:1.3` | `tests/visualization/hamcrest-library.yaml` | `tests/visualization/hamcrest-library.d2` | `tests/visualization/hamcrest-library.svg` |

Чтобы повторно получить D2 для примера, нужен интернет:

```sh
./run.sh tests/visualization/junit.yaml
./run.sh tests/visualization/jupiter-api.yaml
./run.sh tests/visualization/hamcrest-library.yaml
```

Готовые SVG можно открыть в браузере без запуска приложения. Если отдельно установлен компилятор D2, сохранённый текст можно преобразовать в изображение:

```sh
d2 tests/visualization/junit.d2 tests/visualization/junit.svg
```

Для получения нового изображения с текущими настройками:

```sh
./run.sh tests/config.yaml > tests/manual_graph.d2
d2 tests/manual_graph.d2 tests/manual_graph.svg
```

D2 не входит в Python-зависимости и не запускается автоматически из `run.sh`.

### Сравнение с Maven Dependency Plugin

В `tests/visualization/` файлы `*.maven.dot` содержат результат `dependency:tree` в DOT. Файл `comparison.txt` описывает сравнение с D2. Для JUnit получены 3 вершины и 3 ребра, для Jupiter API — 4 вершины и 4 ребра, для Hamcrest Library — 2 вершины и 1 ребро.

При сравнении вершины приводились к `groupId:artifactId:version`: Maven DOT дополнительно содержит `type`, `scope` и отметки `omitted for duplicate`. После такого объединения вершины и рёбра во всех трёх примерах совпали. Раскладка блоков и оформление диаграммы не относятся к составу графа.

Для повторения сравнения отдельно нужны Java, Maven и интернет. Пример для JUnit:

```sh
curl -fsSL https://repo.maven.apache.org/maven2/junit/junit/4.13.2/junit-4.13.2.pom -o tests/visualization/junit.pom
mvn -f tests/visualization/junit.pom org.apache.maven.plugins:maven-dependency-plugin:3.11.0:tree -DoutputType=dot -Dverbose=true -DoutputFile="$(pwd)/tests/visualization/junit.maven.dot"
```

Maven Dependency Plugin используется только для отдельного сравнения, не для построения графа приложением и не в автоматических тестах.
